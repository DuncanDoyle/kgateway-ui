1. **P1 — Malformed query encoding silently removes filters.** [pkg/api/params.go:49](/Users/ddoyle/Development/claude/kgateway-ui-claude/pkg/api/params.go:49) uses `r.URL.Query()`, which discards query parsing errors. For example, `?state=%ZZ` drops the state parameter and returns the unfiltered list with 200. This defeats §7.2’s strict-parameter contract and its stated purpose: preventing unfiltered results from appearing filtered. Parse `RawQuery` with an error-returning parser and reject malformed queries.

2. **P2 — Parent navigation disappears precisely when status is missing.** [ParentCard.tsx:87](/Users/ddoyle/Development/claude/kgateway-ui-claude/web/packages/shell/src/pages/explore/route/ParentCard.tsx:87) takes its link exclusively from a status entry; otherwise it converts the spec parentRef to plain text. The API supplies raw `parentRefs` and creates linked targets only for status entries ([details.go:261](/Users/ddoyle/Development/claude/kgateway-ui-claude/pkg/api/details.go:261)). Consequently, a declared candidate with KGWUI-011 cannot navigate to its visible, owned parent, even though that parent’s detail endpoint returns 200. This leaves §7.1’s requirement to label every rendered reference through admission incomplete. Supply link metadata for spec-only parents without requiring the SPA to infer admission.

3. **P2 — Detail sub-tables suppress notices after failed polls.** [detailParts.tsx:246](/Users/ddoyle/Development/claude/kgateway-ui-claude/web/packages/shell/src/pages/explore/detailParts.tsx:246) renders `PageNotice` only when `l.error && !l.data`. SWR retains data after a same-query poll failure, so previously loaded ListenerSets, attached routes, failed routes, and children remain visible without any error notice. Their badges become unknown, but the detail header can remain fresh because its independent request succeeded. This violates §8.6’s “Error after data: keep the data, show PageNotice” behavior.

4. **P3 — Layout tests assert CSS declarations rather than layout stability.** [details.test.tsx:450](/Users/ddoyle/Development/claude/kgateway-ui-claude/web/packages/shell/src/pages/explore/details.test.tsx:450) compares the header’s `minHeight`; [lists.test.tsx:337](/Users/ddoyle/Development/claude/kgateway-ui-claude/web/packages/shell/src/pages/explore/lists.test.tsx:337) compares declared row heights. These pass when wrapped names or newly arriving header controls increase actual height and move subsequent content. They therefore do not establish §8.6–§8.7’s layout requirements. Browser assertions should compare bounding rectangles before and after loading, including long names at 720 px.

5. **P4 — Empty-match rendering erases a distinction needed by delegation.** [RuleList.tsx:304](/Users/ddoyle/Development/claude/kgateway-ui-claude/web/packages/shell/src/pages/explore/route/RuleList.tsx:304) replaces every empty match array with `PathPrefix /` and labels it “Default match.” The API already supplies that default for *omitted* matches while preserving explicit `[]`. `computed-rules.md` §3.2 and §6 distinguish those inputs: explicit `[]` has special inherit-parent-matcher behavior. The test at [route.test.tsx:383](/Users/ddoyle/Development/claude/kgateway-ui-claude/web/packages/shell/src/pages/explore/route.test.tsx:383) entrenches their equivalence. Preserve the distinction before 2.4 places spec and effective matches together.
