## Problem / goal
kgateway reports a delegation outcome only by writing, or not writing, a child status entry. A child dropped by the matcher fit gets no status at all (`delegation_helpers.go` V4:33-107; D-021 item 6), and no controller output names a child's effective matcher. After 2.3 the HTTPRoute page shows each delegation ref as written and the children with a reported edge. Reproduction: apply `test/e2e/fixtures/observe/06b-matcher-dropped.yaml` on the kind fixture and open parent `shop/api`; child `c6` disappears from Child routes with no reason, and nothing says which of the parent's matches it failed.

Sub-phase 2.4 adds views B and C (D-020): per delegation ref, the routes it selects, their permission, the outcome per path with the ancestor context, and each kept child's effective matches. Each is labelled "computed by the UI" with rule and rule set, and cross-checked by `child-entry` and `parent-resolvedrefs`. KGWUI-011 gains its computed and orphan triggers; KGWUI-012 covers the two new checks. Ownership, counts and install health stay status-based (D-020 rule 4).

## Carried forward from 2.3
- **Listener facts are always shown** to a caller who sees the listener (design §7.4 rule 5; D-023 amended, user 2026-10-26). 2.4 adds no listener fact. Roots read per-route view A outcomes, whose dependencies (route, resource, the `Selector` Namespace, `pkg/computed/kgw23/attach.go:243,330`) stay restricted; every per-route fact of views B and C is dependency-restricted (rules 4 and 6). D-024 removes the same flip for delegation rows: a hidden ancestor route never restricts them; only non-route dependencies of the root still do.
- **The list merges a parent's written-ref checks worst-first**: `disagrees` > `pending` > `unknown` > `restricted` > `checked`, coverage united, `restricted` if any side is (D-023 decision 2; rules §8.4). Route detail keeps each check. Any 2.4 summary of several checks uses the same merge (PF14).
- **D-022 memory gates, in both worlds:** allocation per recompute is reported, not gated. The gates are engine CPU in the sustained stream (≤ 15 % of one core), retained heap (≤ 32 MiB above `bench/2.2-baseline-heap.txt`) and memory from the OS during the stream (≤ 256 MiB), each in the consistent world and the worst case (PF6).

If the p95 flakes, move the clients out of process or tie their count to `GOMAXPROCS` (2.3 P3). Memory from the OS was the closest gate; watch it. `bench-stream` took 20.6 of its 30 min timeout.
- **View B and C code is written in `kgw23` and copied to `kgw24` in Task 59**; only the report keys differ (rules §2, §7). `kgw23` is never edited for a 2.4-only behaviour.

## Known limitations
- **Implicit refs on 2.3 (PF15 of 2.2, user ruling).** A 2.3 child whose parentRef omits the namespace or sets `sectionName` keeps the status-trigger KGWUI-011 warning. Its `child-entry` check is `not-verified`; 2.4 does not remove the warning.
- **Child-edit drops are verified.** The controller clears a dropped child's entry for any cause, observed on both tags (D-021 amendment, 2026-10-26); a current leftover entry is `disagrees` after 30 s.
- **Effective matchers and hostnames are never verified** by the controller; coverage is always `not-verified` (rules §8.4).
- **The orphan finding is install-local.** A parent of another install may still serve the route (rules §8.5).
- **Root dependencies still restrict.** A root admitted through a `Selector` over a hidden Namespace, or a status root with a hidden target, keeps its descendants' rows `restricted` (D-024). This is our call, raised with the user: those facts are decided by hidden labels or objects, not handed over by an ancestor.
- **Status cannot confirm a single path.** Per-rule, per-ref and per-match outcomes collapse into one entry per key (rules §8.2).
