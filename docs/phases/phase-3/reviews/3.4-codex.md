Reviewed `8342a38..7be5182`. Three findings:

1. **P1 — Service explanations overwrite KGWUI-014’s grant diagnosis.**  
   [pkg/health/refs.go:309](../../../../pkg/health/refs.go:309) calls `serviceExplanation` for both 013 and 014. For a cross-namespace ref with `RefNotPermitted`, an absent Service replaces the grant explanation and suppresses its fix. If the Service instead has one different port, [pkg/diagnose/fix.go:68](../../../../pkg/diagnose/fix.go:68) suggests changing the port. Neither change addresses the controller-reported permission failure. Restrict Service explanations and port fixes to 013; §7.3 requires 014 to retain its grant behavior.

2. **P1 — Multi-ref Service attribution omits hidden evidence dependencies.**  
   [pkg/health/refs.go:368](../../../../pkg/health/refs.go:368) records only the faulty Service as a dependency, although lines 349–361 inspect every candidate Service to establish attribution. Consider a visible route referencing visible Service A on a wrong port and hidden Service B. When B has its referenced port, the response attributes the failure to A and offers A’s port fix without `evidenceRestricted`. Changing only B’s ports removes that attribution and fix, while the route’s `BackendNotFound` remains unchanged. This exposes whether the hidden Service has the referenced port. All Services used to establish attribution must participate in the dependency check (§14 rule 12).

3. **P1 — List-only kinds still gate core cache readiness and can raise KGWUI-008.**  
   [pkg/health/checks.go:73](../../../../pkg/health/checks.go:73) excludes list-only kinds only after the `Snapshot.Synced` check. However, [pkg/cache/cache.go:545](../../../../pkg/cache/cache.go:545) includes every dynamic informer when computing `Synced`, and `all()` also includes them when determining `Settled`. If a ReferenceGrant, DirectResponse, or GatewayExtension initial list remains pending after required informers settle, cluster access emits KGWUI-008 (“cache not synced”) and marks the install unknown. The forbidden-list test misses this because an error counts as settled. Optional kinds must also be excluded from core readiness.
