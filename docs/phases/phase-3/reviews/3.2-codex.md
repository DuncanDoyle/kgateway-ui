Found **7 issues: 2 P1, 4 P2, 1 P3**.

1. **P1 — A Gateway with failed scrapes reports proxy stats as available.** [pkg/api/details.go:324](../../../../pkg/api/details.go#L324)  
   `proxyStats()` uses the install-wide check result, without identifying the Gateway. When Gateway A’s proxies all fail but Gateway B succeeds, `proxyStatsCheck.Run` returns an available result with a gap detail; A’s detail consequently returns `available: true`. This conceals A’s missing observations and violates §8.8’s per-Gateway availability requirement. Preserve and expose each Gateway’s scrape availability.

2. **P1 — Events from before startup can raise a false probe-failure finding.** [pkg/cache/events.go:117](../../../../pkg/cache/events.go#L117)  
   A newly encountered Event with count 1 contributes one failure immediately, even when its timestamp predates startup. Three existing `Unhealthy` Events for one Pod can therefore produce KGWUI-020 without any failures observed while watching. §9.2 explicitly excludes pre-start counts. `TestFirstSeenCountIsUnknown` currently reinforces this behavior by counting a pre-existing count-1 Event.

3. **P2 — Proxy evidence discards the numerical counter delta.** [pkg/proxystats/collector.go:289](../../../../pkg/proxystats/collector.go#L289)  
   `observe()` reduces every positive increase to `Seen: true`. Increases of 1 and 500 produce identical evidence; `ProxyTypeRejects` exposes `rejecting` and `rejectingSince`, with no `rejectsSinceLastScrape` count. Task 42 and §13.3 require the per-Pod delta, including the brief’s explicit “1 reject observed since the last scrape” case. The current tests assert boolean growth instead of that observable count.

4. **P2 — The spec-edit stream bypasses the deterministic recompute-rate gate.** [pkg/api/budget_test.go:867](../../../../pkg/api/budget_test.go#L867)  
   `specEditStream.gated` remains false, so this return skips the `rate > 1` assertion below it. CPU is checked separately, but in CI that check only reports. Excessive recomputes in the spec-edit measurement world can thus pass. D-044 explicitly keeps stream recompute counts deterministic and gated everywhere. The authorized timing/reference split does not authorize this omission.

5. **P2 — Initial diagnostics loading still shifts the install layout.** [web/packages/shell/src/pages/install/InstallPage.tsx:120](../../../../web/packages/shell/src/pages/install/InstallPage.tsx#L120)  
   The loading branch deliberately reserves no Needs attention placeholder. When an unhealthy response arrives, its heading, rows and footer are inserted above Processes and inventory, moving everything below. This violates §17.4 and Task 49. The test at `InstallPage.test.tsx:164` waits until rows exist, asserts a CSS `minHeight`, then stalls a subsequent poll; it never checks the initial loading-to-loaded transition or actual element positions.

6. **P2 — The font-ready helper permits the late swap it promises to prevent.** [web/packages/shell/src/shell/renderWhenFontsReady.ts:25](../../../../web/packages/shell/src/shell/renderWhenFontsReady.ts#L25)  
   After three seconds, `Promise.race` renders while font loads remain pending. The bundled fonts use `font-display: swap`, so a later successful load can change text metrics and wrap long names after rendering. Task 48 requires rendering after fonts load or fail; elapsed time establishes neither. A timeout needs a stable fallback strategy or an approved relaxation of the no-shift requirement.

7. **P3 — The retained-heap gate excludes the new watches’ retained state.** [pkg/engine/budget_test.go:584](../../../../pkg/engine/budget_test.go#L584)  
   The measurement stops the live cache, clears `w.Live`, and waits for its goroutines to disappear before measuring retained heap. The snapshot survives, but informer stores, the Pod UID index and Event delta histories do not. §16.3 and Task 52 require the retained-heap budget to include the new watches. This gate cannot detect growth in those structures; the stream OS-memory check measures a different budget.

I did not run tests or edit files. The supplied passing results are author-reported; they do not cover the counterexamples above.
