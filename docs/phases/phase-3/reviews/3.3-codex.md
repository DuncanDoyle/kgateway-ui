Reviewed through `0a196dc`, including the newly added D-055. Six findings:

1. **P1 — Wrong-group detection runs after excluding same-namespace refs.** [pkg/health/refs.go:268](../../../../pkg/health/refs.go#L268)  
   For 014, `field` is reduced to cross-namespace refs before discovery checks it. A route with an invalid-group local backend and one valid cross-namespace backend therefore attributes the failure to the latter and can suggest an unrelated ReferenceGrant. With only the local backend, it misses the corrected-group fix entirely. Design §7.3 requires the wrong-group explanation to run first.

2. **P1 — Unknown discovery state still permits ReferenceGrant YAML.** [pkg/diagnose/fix.go:63](../../../../pkg/diagnose/fix.go#L63)  
   A single cross-namespace ref whose group’s discovery failed receives `Explanation=controller` and `Attributed=true`; this branch then generates a grant. It cannot distinguish a missing grant from a wrong group. Review Focus 2 explicitly requires no fix when the kind’s served state is unknown. The API tests cover unknown discovery for 013, but omit this 014 case.

3. **P1 — Group search results can drill down to zero findings.** [pkg/api/findings.go:256](../../../../pkg/api/findings.go#L256)  
   Groups additionally match their cause’s identity, while flat findings match their own resource/message/detail. The existing `groupsWorld` fixture demonstrates this: `q=shop/cart` returns the Missing backend group, although its route findings say only “Service not found.” The web link preserves that `q` plus `group`, producing an empty flat view. This also contradicts R98’s member-match contract.

4. **P1 — Disconnected log streams retain the “on” state.** [pkg/ctrllogs/collector.go:374](../../../../pkg/ctrllogs/collector.go#L374)  
   `read` errors are discarded, and neither EOF nor closing the connection clears `StateOn`. Subsequent `ErrNotReady` responses also leave the state unchanged. After one successful connection, a restarting container can therefore remain reported as reading logs indefinitely despite no connected stream. Reconciliation keeps publishing fresh values, so collector expiry does not correct this.

5. **P1 — KGWUI-018 measures continuous population size, not an object’s persistence.** [pkg/health/freshness.go:179](../../../../pkg/health/freshness.go#L179)  
   The five-minute timer survives whenever the count stays above threshold, even if every original stuck object recovers and different objects replace them. A rolling sequence of short status delays can consequently raise “Status is not progressing” despite no object having a 003 warning for five minutes. Design §10.2 requires at least one such persistent object; `oldest` is currently used only as evidence.

6. **P2 — Reserved panic retention remains an unrecorded design deviation.** [pkg/ctrllogs/events.go:174](../../../../pkg/ctrllogs/events.go#L174)  
   R102 reserves the newest panic indefinitely, evicting another event when that panic is oldest. Design §8.9 still specifies that the oldest events are dropped. D-055 records other log-reader deviations but omits this exception. Under the requested review rule, the confirmed ruling needs a corresponding decision entry and design amendment.
