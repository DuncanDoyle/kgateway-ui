# Review: 3.0 dense-memory gate change (D-039)
Reviewer: Codex (cross-model) | Author: Claude | Diff: 02e0eb4 | Date: 2026-11-01

1. **P2 — D-039 overstates the memory limit’s guarantee.** [docs/decisions.md:676](../../../../docs/decisions.md#L676) says the binary’s memory limit “keeps the peak inside the pod.” [pkg/app/memlimit.go:35](../../../../pkg/app/memlimit.go#L35) sets a Go **soft memory target**, which cannot guarantee a pod RSS ceiling or prevent excessive live memory. D-025 itself records RSS exceeding the pod limit with the memory limit set. This matters because D-039 presents that target as protection after removing the peak gate. Document it as mitigation, with the remaining peak risk explicit.

2. **P3 — The replacement leaves cold and transient memory growth ungated.** [pkg/engine/budget_test.go:646](../../../../pkg/engine/budget_test.go#L646) measures cold peaks only for logging; the allocation delta starts afterward, and retained heap is measured after collection. A large temporary allocation confined to cold Compute can therefore pass both new gates. Warm computations can also increase simultaneous live memory without increasing total allocated bytes or final retention. These are regressions relevant to D-025’s default-cap pod-memory objective. The supplied unchanged baseline results validate calibration, but don’t establish equivalent regression coverage. A separate bounded-memory workload check would address this gap.

The measurement implementation otherwise looks sound:

- **Allocation window:** includes all five warm recomputes and `forgetViews`, excludes cold Compute and the final GCs. It also includes sampler channels, goroutine/closure, and ticker setup/teardown, so it is slightly broader than exactly the warm loop. This is small harness overhead relative to the approximately 17 MiB margin.
- **Retained heap:** reads `HeapAlloc` after two GCs. `KeepAlive(e)`, subsequent model accesses, and `KeepAlive(snap)` keep the required objects alive.
- **Sampler:** teardown is joined before the final read; sampler accesses are serialized. No race found.
- **Docs/code:** D-039, §16.3, and the implementation plan agree on thresholds, five-child medians, default cap, and logged-only peaks. No P1 correctness bug found.

No files edited or tests run; assessment uses the supplied results.
