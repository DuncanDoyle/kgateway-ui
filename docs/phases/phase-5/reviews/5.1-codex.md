1. **P2 — Legacy options change ownership after `WithPack`.**  
   [pkg/extension/pack.go:58](/Users/ddoyle/Development/claude/snellius-claude/pkg/extension/pack.go:58) snapshots the previous hooks and makes the newest pack own subsequent options and field assignments. Thus `New(WithPack(other), WithComputedRules(f))` applies `f` to `other`, and subsequent `WithDetectors` detectors also claim that pack. Design §4.2’s “Old callers” contract and Task 1 explicitly assign these to the **default pack**. The implementer’s ruling chooses a different contract, and `TestWithPackOnTopOfKgateway` encodes it. Reconcile this deviation before downstreams depend on option ordering.

2. **P2 — The new generic resolution API still defaults to kgateway’s experimental table.**  
   [pkg/install/scope.go:225](/Users/ddoyle/Development/claude/snellius-claude/pkg/install/scope.go:225) treats a nil hook as kgateway classification. `ResolveWith` leaves that hook nil, so a class-only install resolved with nil scope/settings providers can nevertheless classify TCPRoute as experimental-only. This contradicts the designed “nil gives no experimental advice” boundary. The engine masks the problem with `noExperimental`, so its normal class-only path is protected. Preserve legacy classification explicitly in `Resolve`; let generic resolution default to none.

3. **P2 — Process checks do not meet the brief’s class-only availability contract.**  
   [pkg/health/process.go:137](/Users/ddoyle/Development/claude/snellius-claude/pkg/health/process.go:137) starts with an OK result, then adds `not-observed` and “The platform does not report processes.” Probe checks can instead report Events disabled or unavailable before considering whether processes apply. Per-install process sources are deferred to 5.4, but this availability behaviour is explicitly a 5.1 acceptance item.
