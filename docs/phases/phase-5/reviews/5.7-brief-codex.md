1. **P1 — Counts alone do not protect hidden-object information.** `docs/phases/phase-5/phase-5.7-brief.md:37`. `visibleHealth` redacts denied findings but leaves checks untouched (`pkg/api/handlers.go:182–194`); `wireChecks` copies them (`pkg/api/diagnostics.go:459`). A hidden object’s hold would therefore expose its deadline, count changes and potentially identifying `reason` text. Define authorization/redaction for holds, require generic reasons, and test restricted callers. Omitting refs is insufficient.

2. **P2 — Policy-target holds are missing.** `docs/phases/phase-5/phase-5.7-brief.md:62`. `checks.go:484` passes `ctx.WakeAt` into `policyTargets`; `targets.go:105–141` waits before emitting computed KGWUI-016 and verifier KGWUI-012 findings. These are pre-finding holds, including after resource grace expires, when `resource status` can return OK (`checks.go:552`). Add these sites and `targets.go` to scope.

3. **P2 — The 018 acceptance example contradicts existing eligibility and timing.** `docs/phases/phase-5/phase-5.7-brief.md:26`. Deployments are not among the counted status objects (`pkg/health/freshness.go:248–264`), and one stuck object never crosses the minimum-three threshold (`:94–96`, `:267–269`). The deadline also follows the longest-*currently*-stuck object (`:197–199`), so churn can move it beyond `start+5m`. Replace the fixture and specify the existing aggregate behavior; implementing the row literally changes detection rules.

4. **P2 — The stated stream/fingerprint path does not exist.** `docs/phases/phase-5/phase-5.7-brief.md:34`, `:52`, `:63`. `rollup.go:340` fingerprints a check’s output for dependent-check memoization, not a report for client delivery. The engine publishes recomputes (`pkg/engine/loop.go:193–206`), and the SPA polls every five seconds (`web/packages/shell/src/api/hooks.ts:15–29`). Define the actual observable boundary for hold-only changes. Updating `outputPrint` is necessary for check dependencies, but proves no client notification behavior.

5. **P2 — The Gateway-page requirement lacks a response contract and implementation scope.** `docs/phases/phase-5/phase-5.7-brief.md:37`, `:59–66`. Gateway detail currently projects selected check information into `DataPlaneDTO`, rather than returning `CheckResult` (`pkg/api/details.go:267–283`, `:344–364`). Adding `CheckResult.hold` cannot satisfy this row. Specify whether Gateway detail gains a hold field, how it is scoped to that Gateway, and include the API DTO/projection files and tests.

6. **P2 — “Number of held objects” has no consistent counting unit.** `docs/phases/phase-5/phase-5.7-brief.md:22`, `:28`. Endpoints holds are keyed by **Service port** (`pkg/health/endpoints.go:46–52`, `:111–122`), proxy-stat holds by **Pod UID** (`proxystats.go:108–119`), and resource grace deduplicates resources (`checks.go:279–296`). One Service with two empty ports exposes the ambiguity. Define each check’s count and deduplication rules before freezing this public API, especially ahead of Phase 6.

7. **P3 — Manual `Compute` tests can pass with broken deadline scheduling.** `docs/phases/phase-5/phase-5.7-brief.md:48–50`. Calling `Compute` after advancing time forces evaluation independently of the scheduler. A declaration that populates `hold` but fails to preserve `WakeAt` could pass while live clients retain the old result until another trigger. Add a running-engine test with unchanged inputs and safety recomputes disabled; advance the clock and observe the published/API transition.

8. **P3 — Several required positive behaviors have no acceptance coverage.** `docs/phases/phase-5/phase-5.7-brief.md:51–55`. Tests explicitly cover only 018, 023 and resource grace; missing declarations for 025/026, gateway-proxy grace and xDS restart holds could pass. Mixed raised/held results and earliest-deadline aggregation also need assertions. Conversely, “process restart has no hold” already passes today, so `:56`’s requirement that *each* test fail beforehand is too broad.

The optional JSON field appears compatible with existing consumers if `ok`, `pending`, rollup behavior and omission when absent remain unchanged. No files edited.
