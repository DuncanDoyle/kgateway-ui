1. **P1 — Class-only IDs are neither valid for every controller name nor collision-free.** [design.md:161](/Users/ddoyle/Development/claude/snellius-claude/docs/phases/phase-5/design.md:161), plan:83. Gateway API’s `GatewayController` permits additional slashes, underscores and punctuation such as `:` in its path. `example.com/a:b` therefore produces an ID rejected by `pkg/install/id.go:19`. Also, `example.com/a/b` and `example.com/a_b` both become `example.com_a_b`. The workload-ID collision argument does not address collisions between class-only installs. Use an injective encoding or a deterministic hash, with explicit collision tests.

2. **P2 — Finding codes cannot be separated by filtering today’s check objects.** [design.md:184](/Users/ddoyle/Development/claude/snellius-claude/docs/phases/phase-5/design.md:184), plan:128. The core `conditionsCheck` also emits pack-owned findings: `ruleFinding` produces 015 (`pkg/health/checks.go:328`), declared delegation candidates produce 011 (`:450`), and policy-target processing produces 016 and 012 (`:465`, `pkg/health/targets.go:87`). Merely distributing existing checks between `Core()` and `Kgateway()` cannot implement the ownership table. Task 7 needs an explicit extraction or capability dispatch for these branches, preserving finding identities and ordering.

3. **P2 — The claimed complete boundary misses delegation semantics in decoding and reference diagnosis.** [design.md:108](/Users/ddoyle/Development/claude/snellius-claude/docs/phases/phase-5/design.md:108), design:232. `pkg/objects/httproute.go:279` interprets backend references using kgateway delegation rules; `BackendTargets` then excludes those references (`:313`). Core reference diagnosis independently recognizes `delegation.kgateway.dev` and HTTPRoute delegation (`pkg/health/refs.go:79`), changing which missing-kind explanations it supplies (`:291`). `pkg/explore/admit.go:125` also admits named delegation children. Skipping `install.Assign`’s `delegate` call and hiding the endpoint leaves these semantics active. The design needs a boundary for interpretation as well as traversal.

4. **P2 — Policy and Backend semantics are also missing from the boundary audit.** [design.md:108](/Users/ddoyle/Development/claude/snellius-claude/docs/phases/phase-5/design.md:108). `pkg/install/assign.go:329` gives kgateway policies special ownership treatment; `pkg/health/refs.go:182` interprets ListenerPolicy CA configuration; `pkg/health/backend.go:54` judges implementation Backends; and `pkg/api/details.go:635` attaches Backend-specific state. These are functional assumptions, not merely names to allowlist. No task assigns them a pack hook or defines which can intentionally remain shared adapters. Leaving them unspecified makes the seam incomplete before the Backends and Policies phases.

5. **P2 — Experimental-kind behavior has no per-install hook.** [implementation-plan.md:72](/Users/ddoyle/Development/claude/snellius-claude/docs/phases/phase-5/implementation-plan.md:72). The instruction to read the table only for kgateway installs is not implemented by Task 4’s settings/scope/version interfaces. Calls remain in `pkg/health/checks.go:577`, `pkg/api/details.go:441`, and `pkg/engine/views.go:105`. An empty version deliberately applies conservative **kgateway** experimental classification (`pkg/kinds/upstream.go:84`), so class-only installs can receive incorrect experimental-feature advice. Define a classification hook and cover all callers.

6. **P2 — Legacy detector/options compatibility is underspecified.** [design.md:138](/Users/ddoyle/Development/claude/snellius-claude/docs/phases/phase-5/design.md:138), plan:60. Existing `WithDetectors` prepends arbitrary downstream detectors (`pkg/extension/extension.go:95`); those detectors do not belong to a `Pack` or populate `Install.Impl`. Under the proposed empty-Impl/core dispatch, such installs can lose the scope, rules, checks and process behavior old callers expect. State how legacy detectors inherit an implementation, how direct exported registry-field mutations interact with it, and test the existing downstream pattern through engine output.

7. **P2 — Pack collector construction and metrics feedback are not defined.** [implementation-plan.md:119](/Users/ddoyle/Development/claude/snellius-claude/docs/phases/phase-5/implementation-plan.md:119). `Pack.Collectors` contains ready-made collectors, but today construction requires Kubernetes clients, app options, timing and change notifications (`pkg/app/app.go:251–279`); `extension.Deps` supplies none of those (`pkg/extension/deps.go:19`). Nor does it expose a way to install a source into `engine.Config.Metrics`. `setup.Build` also rejects the proposed proxy-stats/controller-logs collector names as reserved (`pkg/setup/setup.go:125`). Task 6 needs a construction/lifecycle contract and corresponding setup changes, not just moving registrations.
