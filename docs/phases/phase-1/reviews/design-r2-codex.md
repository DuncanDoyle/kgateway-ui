The revision is **not ready to implement**. Several accepted findings remain partially resolved.

1. **P1 — Real watch failures can still leave cached data marked readable.** [Plan:1544](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:1544), [Plan:1579](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:1579). Availability depends entirely on `SetWatchErrorHandler`. In the locally installed client-go v0.36.2, `Reflector.watch` retries connection-refused and 429 errors internally without invoking that handler. After initial sync, these failures can therefore leave `Access.OK=true` indefinitely. Expiring an error after 60 seconds also establishes no evidence of recovery. The new test calls `recordError` directly, bypassing the failing production path. Accepted finding **2 remains unresolved**.

2. **P1 — Unprocessed resources still become healthy during grace, and Pending policies can remain healthy indefinitely.** [Plan:4216](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:4216), [Plan:4312](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:4312), [Plan:4331](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:4331). During grace, pending status produces no finding, but the required status check still returns OK. With other signals healthy, the roll-up becomes healthy. Furthermore, current policy conditions with reason `Pending` are silently ignored at every age. Upstream v2.4.7’s `ancestorRefConditionsWithDefaults` explicitly produces `Accepted=False/Pending` and `Attached=False/Pending`. Both paths contradict design §5.2’s requirement that absent/unprocessed evidence never counts as health. Finding **1 is only partially fixed**.

3. **P1 — Zero observed generation bypasses the promised freshness rule.** [Plan:939](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:939). `IsStale` explicitly exempts `observedGeneration=0`. An object at generation 2 with required True conditions at generation 0 can consequently report healthy; False conditions can become current errors. [Design:207](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/design.md:207) defines either as stale. Missing generation evidence needs an explicit unavailable/pending outcome rather than unconditional freshness.

4. **P1 — Missing listener status blocks escape the missing-status check.** [Plan:4257](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:4257). Listener checks iterate only `status.listeners`; they never compare those entries with `spec.listeners`. A Gateway with current top-level Accepted/Programmed conditions but no status for a configured listener passes without KGWUI-003. The revision detects missing conditions inside existing blocks, but misses an entirely absent block. This leaves another hole in accepted finding **1**.

5. **P1 — Parent matching discards `port`, allowing removed-parent status to remain eligible.** [Plan:757](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:757), [Plan:4271](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:4271). Neither `ParentRef` nor `rawRef` carries Gateway API’s `port`. Changing a parent from Gateway port 80 to port 443 therefore leaves the decoded references equal, so status for the removed port can satisfy the new reference. Multiple port-specific parents also collide and the last matching status wins. Preserve port, including unset versus specified, in parent-status equality. Finding **5 is incomplete** despite the corrected object ownership lookup.

6. **P1 — Cluster-level health still has no freshness protection.** [Plan:5266](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:5266), [Plan:8810](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:8810). `InstallSummary` carries no collection timestamp, and cluster cards and the install switcher render its health directly. If computation stalls while HTTP continues serving the last model, successful polls can show an old healthy state indefinitely. The install page now checks timestamps, but these other health surfaces cannot. Accepted finding **3 is only partially resolved**.

7. **P2 — The design still instructs implementations and tests to drop restricted findings.** [Design:325](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/design.md:325), [Design:380](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/design.md:380). These passages respectively say denied findings are dropped and absent from API output. They contradict §7.1’s next bullet, D-013, the user’s required contract, and the plan’s correct `visibleHealth` implementation. Replace both instructions with retained restricted findings and unchanged roll-up/counts. **A3 is not consistently resolved across documents.**

8. **P2 — Mixed attached/missing-parent routes have conflicting count contracts.** [Design:152](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/design.md:152), [Plan:2238](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:2238). The design says a route targeting a nonexistent parent is not counted in any install. The plan explicitly allows a route to be owned through one parent and unattached through another; `Assign` then includes it in route totals. Choose one observable behavior and align design, implementation steps and API assertions. Finding **9 is implemented, but inconsistently specified**.

9. **P2 — The public override contract still excludes `Shell`.** [Plan:7893](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:7893). The revised contract requires every component exported from the shell package to accept `stylesOverride`, but exported `Shell` accepts only `extension` and `pages`. It is neither a page-internal styled part nor covered by that exception. Accepted finding **17 remains partially unresolved**.

10. **P3 — Required API-boundary coverage is still missing or too weak.** [Plan:4831](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:4831). The new table checks finding presence for stale True, absent conditions and missing ancestors, but leaves expected state empty; it also does not reject an additional incorrect current-error finding. Its shared world already contains an unrelated warning. There are no HTTP-boundary cases for stale False, removed/foreign-install parent status, foreign-group references, new generic policies, or post-sync watch failures across dynamic and typed informers. Those cases remain unit-only or absent despite design §9 requiring API behavior. Add isolated inputs and assert state, severity, absence of incorrect findings, and inventory counts.

11. **P3 — The captured-metrics test still does not verify reject values.** [Plan:2842](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:2842). Reject-label assertions run only when captured samples exist, so reject-free captures pass vacuously. The test never asserts a parsed reject value from either real capture. Assertions against the synthetic `sample` do not verify the upstream contract. Accepted finding **15’s metrics portion remains open**; capture a known reject and assert its Gateway identity, labels and parsed value.

I found no remaining issue with the prescribed fixes for **4, 6, 7, 8, 10–14 or A2**. The restricted-finding implementation preserves severity/code/ref, clears message/evidence, retains total roll-up/counts, and prevents frontend links; the conflicting design instructions above remain.
