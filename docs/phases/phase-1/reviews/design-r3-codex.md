**The plan is not ready to implement.** Five issues remain.

1. **P1 — A successful probe list can clear an ongoing watch failure.** [implementation-plan.md:1798](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:1798). `Probe` deletes the informer’s recorded error whenever its independent `limit=1` list succeeds. That neither verifies watch permission nor refreshes the informer store. With `list` allowed but `watch` forbidden, probes repeatedly restore `Access.OK` while the cached objects remain outdated. Recovery can also be declared before a disconnected informer catches up. Accepted row **1 remains incomplete**: recovery needs evidence from the informer’s synchronization path.

2. **P1 — One hanging kind probe can stop availability checks indefinitely.** [implementation-plan.md:1793](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:1793), [implementation-plan.md:1809](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:1809). Lists execute serially with the application-lifetime context and no configured request deadline. A stalled response prevents all subsequent probes, while `HasSynced` and previously successful access remain usable indefinitely. Engine recomputation keeps refreshing report timestamps. Moreover, client-go v0.36.2’s `ServerVersion()` uses `context.TODO()` and defaults to a 32-second timeout, exceeding the advertised 10-second cadence. Bound requests/cycles and expire old probe evidence. The stated ~2.5 requests/s is a nominal successful-cycle estimate, not a bounded execution contract.

3. **P1 — `SpecChangedAt` measures non-status writes, not spec changes.** [implementation-plan.md:1030](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:1030). Taking every non-status managedFields timestamp includes label, annotation and finalizer updates. For example, a controller updating an annotation every 30 seconds keeps an old unprocessed resource inside grace forever, replacing the promised warning with “Being processed.” This affects client-side apply, server-side apply, `kubectl edit`, and controller updates; their managedFields timestamps are not restricted to spec mutations. [Kubernetes documents these timestamps as field-manager activity](https://kubernetes.io/docs/reference/kubernetes-api/definitions/managed-fields-entry-v1-meta/). Track generation/spec transitions with a defined startup fallback; the synthetic timestamp test does not establish the claimed semantics.

4. **P1 — Fresh summaries can remain green after becoming stale.** [implementation-plan.md:7852](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:7852), [implementation-plan.md:9468](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:9468). `isStale` runs only during rendering. If computation stalls and successful HTTP polls return the identical model, [SWR suppresses rerenders for unchanged data](https://swr.vercel.app/docs/advanced/performance#deep-comparison). Cards, header and switcher can therefore retain their healthy presentation indefinitely. Accepted row **6 remains incomplete**. Add a reactive clock/deadline and test a fresh response aging past the threshold while identical successful responses continue.

5. **P2 — Missing-parent findings contradict the revised multiplicity contract.** [design.md:152](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/design.md:152), [implementation-plan.md:4562](/Users/ddoyle/Development/claude/kgateway-ui-claude/docs/phases/phase-1/implementation-plan.md:4562). The design requires one KGWUI-003 per missing parent, but `reported` deduplicates by resource identity. Two missing parents produce only one finding; an earlier pending owned parent can suppress every missing-parent diagnostic. Inventory counting from accepted row **8** is aligned, but diagnostic multiplicity is not.

Accepted rows **3–5, 7, 9–11** are resolved in the reviewed instructions; row **2** correctly implements info/Pending → unknown, subject to the grace-clock issue above. I found no additional identifier/signature blocker. The `policySeverity` Pending arm is redundant for Accepted/Attached, but does not warrant a separate correctness finding.

Task 1’s reject trigger is plausible on **both v2.3.11 and v2.4.7**: the tagged fixture exists, standard validation passes through the invalid TLS parameters, and the reject callback emits the expected labels and stripped CDS type URL. The revised capture test requires a real parsed reject.

## Triage

| 1 | Probe list success clears an ongoing watch failure | reviewer | accept, simpler design | Drop the probes entirely. Each informer gets an instrumented ListerWatcher (`cache.ListWatch` around the dynamic/typed client) that records the outcome of every List and Watch call the reflector makes, including the connection-refused and 429 retries the error handler never sees. A kind is unavailable from its last failed call until its next successful Watch call. Evidence then comes from the informer's own sync path, and there is no extra API load. |
| 2 | A hanging probe stops availability checks | reviewer | accept, resolved by #1 | No probes, nothing to hang. Lists use a request timeout; watches rely on client-go's server-side watch timeout (re-established every 5–10 min). The residual case, a silently stalled TCP stream, is documented as a known limit. |
| 3 | `SpecChangedAt` counts label/annotation/finalizer writes | reviewer | accept, simpler design | Drop `managedFields` parsing. The engine remembers when it first saw each (uid, generation); grace runs from that moment. Objects present at UI start get grace from start, so after a restart stale status shows "being processed" for 60 s, then a warning. |
| 4 | Stale summaries stay green under unchanged SWR data | reviewer | accept | A shared clock hook re-renders every second; every staleness check reads it. Test: a fresh response ages past the threshold while identical responses keep arriving. |
| 5 | One KGWUI-003 per resource, not per missing parent | reviewer | accept | Deduplicate missing-parent findings by (resource, parentRef). |
