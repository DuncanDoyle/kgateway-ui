1. **P1 — Unrelated publications can indefinitely prevent a complete Gateway map.**  
   [pkg/api/paths.go:129](/Users/ddoyle/Development/claude/snellius-phase6/pkg/api/paths.go:129), [mapData.ts:90](/Users/ddoyle/Development/claude/snellius-phase6/web/packages/shell/src/pages/map/mapData.ts:90).

   Revision uses the global `Model.Seq`, which increments on every computation, including publications unrelated to the selected Gateway. Every mismatch discards the continuation and restarts; after three attempts, line 101 returns the previous result or the last attempt’s prefix.

   Consequently, if publications arrive more frequently than a complete sequential walk can finish, **no poll can complete**, even when this Gateway’s paths never change. For example, ten pages taking 200 ms each cannot fit between publications approximately one second apart. A previously loaded map freezes; an initial load repeatedly retains a prefix. Revision checking needs a way to make progress under unrelated churn, such as snapshot paging or a revision scoped to the relevant result.

2. **P1 — Tolerating a delegated-child rejection can hide a separate programming failure.**  
   [pkg/explore/rows.go:341](/Users/ddoyle/Development/claude/snellius-phase6/pkg/explore/rows.go:341), [pkg/paths/project.go:573](/Users/ddoyle/Development/claude/snellius-phase6/pkg/paths/project.go:573).

Preserve independent failures before applying the specific rejection tolerance. This leaves earlier finding 3 incomplete.
